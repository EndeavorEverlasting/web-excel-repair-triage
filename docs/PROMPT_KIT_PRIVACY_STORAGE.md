# Prompt Kit Privacy and Storage Boundaries

This document is the human-readable companion to `harness/contracts/prompt-kit-cross-device-access.v1.json`. The machine-readable contract is authoritative when prose and implementation drift.

## Core rule

Prompt Kit separates four data planes:

1. **Prompt Canon** — shared product truth: prompts, public classifications/topology, schemas, validators, eval definitions, release manifests, and hashes.
2. **Personal State** — user-owned durable state on the user's device: Favorites, collections, saved variants, preferences, personal tags, and explicitly saved notes/workflows.
3. **Private Sync** — a portable encrypted save protocol for the allowlisted subset of Personal State.
4. **Collective Learning** — privacy-reduced aggregate behavioral evidence only. It must not become a user/session/project tracking system.

The governing invariant is: **GitHub contains product truth; static hosting contains public distributable truth; the user's device contains personal truth.**

## What belongs in the GitHub repository

The repository is the source/build/validation factory. It may contain only product-level source and sanitized fixtures, never a user's Prompt Kit save or raw usage state.

Canonical examples include:

```text
web-excel-repair-triage/
├── docs/prompts.json                              # base Prompt Canon source
├── registry/prompts/                              # registered prompt/product ownership data
├── harness/contracts/
│   └── prompt-kit-cross-device-access.v1.json     # privacy/storage/access authority
├── scripts/
│   ├── build_prompt_kit_registry.py               # canonical Prompt Kit builder
│   └── validate_prompt_kit_privacy_storage.py     # privacy/storage boundary validator
├── tests/
│   └── test_prompt_kit_privacy_storage.py         # rejection/regression proof
├── web/
│   ├── prompt-kit/index.html                      # checked-in generated canonical app
│   ├── prompt-kit/resources.v1.json               # public resource index
│   ├── prompt-kit-mobile/                         # public launcher/PWA source
│   ├── prompt-kit-legacy-redirect/                # public compatibility redirect
│   ├── operant-legacy-redirect/                   # public compatibility redirect
│   └── roster-log-v2/                             # separate public static app
└── .github/workflows/
    ├── prompt-kit-pages.yml                       # canonical Pages package/deploy path
    └── prompt-kit-privacy-storage.yml             # privacy/storage contract gate
```

`web/prompt-kit/index.html` remains generator-owned. Repair its canonical inputs/generator and regenerate; do not hand-edit generated HTML to implement privacy/storage behavior.

## What GitHub Pages publishes

The deployment is built by `.github/workflows/prompt-kit-pages.yml`; there is no separate hand-maintained `public/` tree. The workflow currently constructs this public bundle:

```text
GitHub Pages site root
├── index.html / manifest.webmanifest / service-worker.js / icons
│   └── source: web/prompt-kit-mobile/
├── afk-agent-flow/
│   ├── index.html
│   │   └── generated by scripts/build_prompt_kit_registry.py
│   │       and byte-compared with web/prompt-kit/index.html
│   └── resources.v1.json
│       └── source: web/prompt-kit/resources.v1.json
├── prompt-kit/index.html
│   └── source: web/prompt-kit-legacy-redirect/index.html
├── operant/index.html
│   └── source: web/operant-legacy-redirect/index.html
└── roster-log-v2/
    └── source: web/roster-log-v2/
```

The generated canonical app is therefore published at `/afk-agent-flow/index.html`; it is not a separately edited public copy.

The privacy/storage workflow watches the recursively copied public source trees plus `docs/prompts.json`, `registry/prompts/**`, and `scripts/build_prompt_kit_registry.py`. That keeps the privacy gate attached to changes that can alter the public bundle rather than only to changes in this document or validator.

The validator also asks Git directly for the currently tracked files under the public source roots using `git ls-files`. It rejects tracked paths that look like Prompt Kit private runtime state, encrypted save files, recovery/key material, environment files, or common credential/secret artifacts. `.gitignore` is defense in depth for files that are not yet tracked; it is not treated as proof that an already tracked artifact is safe to publish.

The public AFK Agent Flow URL is:

```text
https://endeavoreverlasting.github.io/web-excel-repair-triage/afk-agent-flow/
```

The rule for static hosting is intentionally severe: **publish a file only when anonymous worldwide download is acceptable.**

GitHub Pages must never publish Personal State, Local Journal records, encrypted save files, user/session/device/vault identifiers, private project context, recovery material, encryption keys, or PrivacyReducer buffers.

## What stays only on the user's device

A concrete implementation may use IndexedDB in a browser, SQLite or another embedded store in a desktop/mobile application, and platform-protected key storage for secrets. Those technology choices do not change logical ownership.

```text
Prompt Kit local state
├── public_cache
│   └── re-creatable Canon/static assets
├── personal_state
│   ├── favorites
│   ├── collections
│   ├── saved variants
│   ├── preferences / personal tags
│   └── explicitly saved notes/workflows
├── local_journal
│   └── raw prompt usage, execution, correction, project and task context
├── privacy_reducer_buffer
│   └── locally aggregated evidence awaiting its privacy threshold
├── sync_state
│   └── local capsule/base and encrypted-export metadata
└── secrets
    └── encryption/recovery material in protected storage where available
```

**The raw Local Journal history stays on the device.** It is not eligible for Private Sync even merely because encryption is available.

## Portable Private Sync v1

Private Sync v1 is a protocol, not a Prompt Kit-owned cloud service.

Prompt Kit may create:

```text
promptkit-save.pkenc
```

The plaintext Sync Capsule is built by positive allowlist only and may include:

- schema and compatible Canon version;
- Favorites;
- collections;
- saved user-created variants;
- preferences and personal tags;
- explicitly saved notes;
- saved workflows.

Before any transport, the capsule must be encrypted. Raw prompt/execution history, the Local Journal, project/repository/customer/file-path context, session/device/account/vault identifiers, reducer buffers, and recovery/key material are forbidden **before encryption** and therefore never become part of the save capsule.

The encrypted file may then be carried by storage the user already has: OneDrive, Google Drive, iCloud, Dropbox, Syncthing, a NAS, USB, or ordinary file transfer.

**No Prompt Kit-owned backend is required for v1.** Automatic hosted synchronization is a future transport option and must preserve the same capsule boundary rather than widening it to raw local history.

## PrivacyReducer boundary

PrivacyReducer is the only authorized transformation from rich local behavior into Collective Learning evidence. The reducer itself has no network authority.

Allowed output is limited to bounded product-level fields:

```text
schema_version
canon_version
prompt.prompt_id
prompt.prompt_version
behavior.action
behavior.outcome
behavior.correction_bucket
behavior.retry_bucket
behavior.duration_bucket
transition.from_prompt
transition.to_prompt
count
```

It must reject identity, persistent pseudonyms, Private Sync/vault identifiers, device/browser identifiers, sessions/conversations/traces, project/repository/customer/file-path context, raw user/prompt/agent/error text, and exact activity timestamps. Hashing or renaming a forbidden identifier does not make it acceptable.

The v1 local batching profile requires at least 5 equivalent local observations, at least 3 distinct aggregate keys, at least 6 hours of batch age, a randomized 12–24 hour flush window, and a maximum 90-day aggregate buffer. Network upload/ingestion is not implemented by this contract.

## Relationship to existing feedback work

This contract does not replace the repository's feedback, outcome-receipt, or AFK routing domains. Those lanes may collect or classify their own explicitly governed evidence. They do not gain permission to bypass the Sync Capsule or PrivacyReducer boundaries defined here.

In particular, a session identifier that is appropriate inside an explicitly local feedback/diagnostic owner is **not** automatically eligible for Collective Learning output or Private Sync.

## Proof ceiling

Repository validation can prove the contract, rejection tests, `.gitignore` defenses, tracked-public-source path checks, and consistency with the current GitHub Pages packaging workflow. It cannot prove physical browser/device storage behavior, cryptographic implementation, `.pkenc` import/export, cross-device pairing, a hosted sync service, network anonymity, or live Collective Learning ingestion until those runtime capabilities exist and are observed.
